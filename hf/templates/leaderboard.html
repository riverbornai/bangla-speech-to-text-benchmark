Bangla Speech-to-Text Leaderboard

Which speech-to-text API understands Bangla best? We sent the same 1,001 real Bangla recordings, from news bulletins to children's voices, to 8 hosted APIs in batch and live streaming mode, and scored every transcript.

The short answer

    Key findings

    Character error rate (CER) is the share of characters that a transcript gets wrong. 6.9% CER means about 7 errors in 100 characters.

    01

    Bangla specialists win

    Sarvam (6.9%) and Soniox (8.1%) lead batch, and change places in streaming. The gap between them is small, but statistically real.

    02

    Live can beat batch

    The Soniox real-time model (7.4%) was more accurate than its own batch model (8.1%). Streaming does not always mean lower accuracy.

    03

    Big global names trail

    OpenAI gpt-4o-transcribe (28.7%) and Whisper large-v3 (30.7%) make 4 to 5 times the errors of the leaders on Bangla.

    04

    Domain matters a lot

    ElevenLabs is mid-table overall (14.7%), but it gets 47.1% CER on medicine. Check the domain that is nearest to your audio.

    05

    Cheapest is near the top

    Soniox batch costs $0.10 per audio hour, one tenth of Google Chirp 2, and has the second-best accuracy.

    06

    Streaming latency varies 5×

    After the speaker stops, Sarvam gives the final transcript in 0.9 s (median). OpenAI takes 4.2 s and Gemini Live takes more than 10 s.

    Head-to-head: is the difference real?

    A paired bootstrap over the clips that both providers transcribed tells you if the gap between neighbours in the ranking is real or noise.

    “Ahead” means the 95% interval of the CER gap does not include zero. “Tie” means that the test cannot separate the two providers.

    Method

    The full details are in the GitHub README, down to the prompt and the normalization rules.

    Test set: 1,001 clips from BanSpeech

    We sampled 77 clips at random from each of the 13 domains of BanSpeech (SUST CSE Speech Group, CC BY-NC 4.0). Regional dialect clips are not included. Clips are 16 kHz WAV, 0.7 s to 26.8 s long (median 2.1 s), 50.0 minutes in total, with 7,996 reference words and 43,411 characters. 97% of clips are shorter than 10 seconds, like voice commands and conversation turns.

    Metrics: CER, WER and confidence intervals

    CER (primary) is the number of character substitutions, deletions and insertions that change a transcript into the reference, divided by the reference length. WER is the same at word level. Both are corpus-level: total edits across all clips divided by total reference length, not an average of per-clip rates.

    We rank on CER because Bangla word spacing is not consistent between annotators and engines. One spacing difference, for example a split compound, counts as two word errors even when every letter is correct. This is why WER is much higher than CER for every provider.

    95% confidence intervals come from 10,000 bootstrap resamples of the clips. A failed request is not included in the score of that provider. It is not counted as 100% error. Every provider covered at least 99.4% of the clips.

    Text normalization

    The same normalizer runs on the references and on every transcript before scoring, so formatting choices do not count as errors:

    • Unicode NFC normalization.
    • Remove zero-width characters (ZWNJ, ZWJ, BOM).
    • Map Bangla digits ০–৯ to 0–9.
    • Replace punctuation (including the danda ।) with a space.
    • Lowercase Latin text, then collapse whitespace.

    Without this step, formatting choices alone change scores by 10 to 20%. Source: src/normalize.py.

    Batch and streaming setup
    • Batch: one request for each clip, one at a time. Latency is the wall-clock request time.
    • Streaming: 16-bit PCM audio, sent in 100 ms chunks. Each chunk is sent only after that much real time has passed, like a live microphone. Accuracy is scored on the final transcript, so the batch and streaming tables are directly comparable.
    • Settings: provider defaults, except for the language. No custom vocabulary and no fine-tuning. Only Gemini batch received a prompt (“Transcribe this Bengali (Bangla) audio verbatim…”).
    • Environment: a MacBook in Bangladesh on a regular internet connection. Provider servers were in the US, Europe or India. Google Chirp 2 ran in us-central1.

    Pricing

    • Groq bills at least 10 seconds for each request. On our short clips, it costs 3.4× its list price.
    • Sarvam and Google round each request up to the next second. This adds about 17% on our clips.
    • Soniox real-time bills the streaming session time, which includes the wait for the final transcript. This adds about 40% on our clips.
    • Sarvam prices in rupees. We converted at ₹95.96 per US$ (ECB reference rate, 24 September 2026).
    • Token-billed prices (Soniox, OpenAI) are estimates. Gemini prices are minimums, because they include only the audio input.
    Limitations
    • Mostly read and broadcast speech. No phone audio, heavy noise, regional dialects or Bangla-English code-switching.
    • Language tags are different for each provider (bn, bn-IN, bn-BD, ben). This can have an effect on the results.
    • Gemini Live returned no interim transcripts, and its adapter set no language hint.
    • ElevenLabs batch requested scribe_v1, which was scheduled for removal. Every request succeeded, so we cannot tell which version served them.
    • Latency includes the network distance from Bangladesh, which has a different effect on each provider.
    • Only hosted APIs were tested. Self-hosted open-weight models are not included in v1.0.

    FAQ

    What is the best speech-to-text API for Bangla?

    In our September 2026 test, Sarvam AI (saarika:v2.5) was the most accurate for recorded audio at 6.9% CER. Soniox (stt-rt-v5) was the most accurate for live streaming at 7.4%. Soniox batch was a close second at 8.1%, and it was the cheapest option that we tested.

    What is the best real-time (streaming) API for Bangla?

    Soniox (stt-rt-v5) was the most accurate streaming API at 7.4% CER, statistically ahead of Sarvam AI (9.0%). Sarvam gave the final transcript fastest after the speaker stopped (0.9 s median, against 2.5 s for Soniox). Thus Sarvam can be a better fit for voice agents that must reply quickly.

    What is the cheapest speech-to-text API for Bangla?

    Soniox was the cheapest in both modes: $0.10 per audio hour for batch and $0.17 for streaming (effective price on our clips). It also had the second-best batch accuracy (8.1% CER). Google Cloud Speech-to-Text (Chirp 2) was the most expensive at $1.12 per hour. We checked prices on 24 September 2026.

    How accurate is Google Cloud Speech-to-Text (Chirp 2) on Bangla?

    Chirp 2 (language bn-BD) scored 21.9% CER in batch and 23.6% in streaming. It ranked 6 of 8 in batch. Google Gemini 2.5 Flash did better in batch at 13.3%, but poorly through the Live API (69.6%).

    Does Whisper work well for Bangla?

    Not on this test. Whisper large-v3 (served by Groq) scored 30.7% CER and 71.7% WER. This was the lowest accuracy of the 8 batch APIs, about 4.5 times the error rate of the leader. It was the fastest to respond (0.66 s for each clip). Groq has no streaming API.

    Which Bangla language code should I use: bn, bn-BD or bn-IN?

    Use the code that the provider supports. In this benchmark, Sarvam used bn-IN, Google Chirp 2 used bn-BD, ElevenLabs used ben, and Deepgram, OpenAI, Groq and Soniox used bn. The audio is standard Bangla from BanSpeech (SUST, Bangladesh). We did not test if a different code changes the accuracy.

    Does it cover phone calls, dialects or code-switching?

    No. The audio is mostly read and broadcast-style standard Bangla in 13 domains. Regional dialect clips were not included, and there are no phone calls, heavy noise or Bangla-English code-switching. Test on your own audio before you choose a provider.

    Can I reproduce the results?

    Yes. The repository has the test set definition, the provider adapters, the scoring code and the confidence-interval code under the MIT license. Add your API keys and run the scripts. You can also check the published numbers with no API keys: the per-clip results are in the results dataset.
